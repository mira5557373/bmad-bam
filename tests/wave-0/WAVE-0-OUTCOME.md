## What "Plan A PASS" means and does NOT mean

**Verified (headless, against both spec-mandated skills):**

1. The literal universal-glob string `file:{project-root}/**/project-context.md` survives BMAD's three-layer customize merge into BOTH `bmad-create-architecture` and `bmad-create-prd`'s resolved persistent_facts.
2. The sentinel `_bmad/platform/project-context.md` (generated by `src-v6/bmad-bam-platform/scripts/post-install.sh`) is present at a `**`-matching path with a fresh `BAM_LOAD_VERIFY_<uuid>` token.
3. `bmad-create-architecture` lives under `[workflow]` namespace; `bmad-create-prd` lives under `[workflow]` namespace. The smoke-test helper (`tests/wave-0/lib/inspect-context.sh`) queries BOTH `[agent]` and `[workflow]` namespaces and treats presence in either as a hit. This namespace split was a refinement on Task 0's investigation (originally examined only agent skills).

**NOT verified by the headless runner (by design — see Task 0 / INVESTIGATION-NOTES.md):**

4. The LLM, at activation time, actually parses the `file:` prefix in either `agent.persistent_facts` or `workflow.persistent_facts`, expands the `**` glob, locates `_bmad/platform/project-context.md`, reads its contents, and treats it as foundational context. This contract lives in 30 separate BMAD SKILL.md prompts. It is by-design untestable without a live LLM session. The architecture spec §7.3 acknowledges this gap.

Plan C (manual LLM verification — see `src-v6/bmad-bam-platform/skills/bmad-bam-smoke-test/steps/step-07-v-verify-plan-c.md`) is the path to verify the full end-to-end chain. A real-install verification should be scheduled before P2 ships, as a one-time confirmation that the LLM-side contract holds.

## Implications for P2 (bmad-bam-platform full module)

- **Plan A holds against multiple skills:** P2 can rely on universal-glob auto-load for activation. **No install-time overlay code is required** in BAM modules' post-install hooks (Plan B remains dead code unless a future BMAD release breaks the universal-glob).
- **BAM module customize.toml files MUST opt in to the universal-glob themselves.** Per Task 0 risk #2, the universal-glob is opt-in per skill, not a global runtime hook. Every `bmad-bam-<x>/customize.toml` must include `persistent_facts = ["file:{project-root}/**/project-context.md", ...]` in either its `[agent]` or `[workflow]` block depending on skill type. The `bmad-bam-smoke-test` skill demonstrates this (committed in remediation).
- **Plan C must remain documented but is not the primary path.** Keep `step-07-v-verify-plan-c.md` as the fallback workflow. Real-install verification of Plan A's part 4 (LLM-side loading) should be performed once during P2 acceptance to ratify the headless result against a live agent.
- **Sentinel file location is canonical.** P2 modules must emit their `_bmad/<module>/project-context.md` at `**`-matching paths under `{project-root}`. BAM uses `_bmad/<module>/project-context.md` to keep modules isolated; the spec mentions `_bmad-output/project-context.md` as the BMAD-documented canonical location.
- **Resolver requires Python 3.11+.** Enforced by both `tests/wave-0/run-smoke-test.sh` pre-flight and `src-v6/bmad-bam-platform/scripts/post-install.sh` post-remediation.
- **Family.json schema is now canonical:** `_bmad/bam/schemas/family.schema.json`. P2 producers must conform.

## Plan-spec divergences encountered during Wave 0 (for future plan authors)

1. **Plan's verify-Plan-A/B/C step files contained Node.js pseudocode** (`require(...).forSkill(...)`) and grep-for-sentinel-UUID semantics. Both were wrong: BMAD v6.6.0 ships a Python resolver, and the resolver does not expand `file:`/globs (so the sentinel UUID never appears in resolved JSON). Tasks 13-15 and 17 substituted the correct mechanism per Task 0's findings.
2. **Plan's Task 5 awk verification was naive about quoted commas**; the CSV is valid (per `csv.DictReader`).
3. **Plan's runner originally targeted one skill (`bmad-agent-analyst`)**, not the spec-mandated two (`bmad-create-architecture` + `bmad-create-prd`). Corrected in remediation (C3).
4. **Task 0's resolver invocation generalised over agent skills only**; workflow skills require `--key workflow.persistent_facts`. Corrected in remediation (helper now queries both).
5. **Plan's `module.yaml` had `install:`/`verify:`/`requires:` blocks BMAD's installer doesn't read.** Corrected in remediation (C2) — those moved under `x-bam-*` keys with explicit "not consumed by BMAD installer" comments.
6. (Self-inflicted) Heredoc copy-paste error in Task 1 commit message during subagent prompt construction; amended in-place.
