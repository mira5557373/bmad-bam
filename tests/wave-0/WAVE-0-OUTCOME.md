## What "Plan A PASS" means and does NOT mean

**Verified (headless):**

1. The literal universal-glob string `file:{project-root}/**/project-context.md` survives BMAD's three-layer customize merge (`resolve_customization.py`) into the target skill's resolved `agent.persistent_facts`. Target skill: `bmad-agent-analyst` (from `external/bmad-method/src/bmm-skills/1-analysis/`), confirmed by Task 0 to ship the universal-glob in its base `customize.toml`.
2. The sentinel `_bmad/platform/project-context.md` (generated by `src-v6/bmad-bam-platform/scripts/post-install.sh`) is present at a path the `**`-recursive glob would match, and it contains the freshly-minted `BAM_LOAD_VERIFY_<uuid>` token.

**NOT verified by the headless runner (by design — see Task 0 / INVESTIGATION-NOTES.md):**

3. The LLM, at activation time, actually parses the `file:` prefix in `agent.persistent_facts`, expands the `**` glob, locates `_bmad/platform/project-context.md`, reads its contents, and treats it as foundational context. This contract lives in 30 separate BMAD SKILL.md prompts. It is by-design untestable without a live LLM session. The architecture spec §7.3 acknowledges this gap.

Plan C (manual LLM verification — see `src-v6/bmad-bam-platform/skills/bmad-bam-smoke-test/steps/step-07-v-verify-plan-c.md`) is the path to verify the full end-to-end chain. A real-install verification should be scheduled before P2 ships, as a one-time confirmation that the LLM-side contract holds.

## Implications for P2 (bmad-bam-platform full module)

- **Plan A holds:** P2 can rely on universal-glob auto-load for activation. **No install-time overlay code is required** in BAM modules' post-install hooks (Plan B is dead code unless a future BMAD version breaks the universal-glob).
- **BAM module customize.toml files MUST include the universal-glob themselves.** Per Task 0 risk #2, the universal-glob is opt-in per skill, not a global runtime hook. Every `bmad-bam-<x>/customize.toml` (when P2+ ships any) must include `persistent_facts = ["file:{project-root}/**/project-context.md", ...]` in its `[agent]` block.
- **Plan C must remain documented but is not the primary path.** Keep `step-07-v-verify-plan-c.md` as the fallback workflow. Real-install verification of Plan A's Part 3 (LLM-side loading) should be performed once during P2 acceptance to ratify the headless result against a live agent.
- **Sentinel file location is canonical.** P2 modules must emit their `_bmad/<module>/project-context.md` at `**`-matching paths under `{project-root}`. The BMAD-documented canonical location (`_bmad-output/project-context.md`) is one option; BAM uses `_bmad/<module>/project-context.md` to keep modules isolated.
- **Resolver requires Python 3.11+.** P2's pre-install checks should refuse to install on hosts below that floor.

## Plan-spec divergences encountered during Wave 0 (for future plan authors)

Recorded here for the BAM v6 team's future planning:

1. **The plan's verify-Plan-A/B/C step files contained Node.js pseudocode** (`require(...).forSkill(...)`) and grep-for-sentinel-UUID semantics. Both were wrong: BMAD v6.6.0 ships a Python resolver, and the resolver does not expand `file:`/globs (so the sentinel UUID never appears in resolved JSON). Tasks 13-15 and 17 substituted the correct Python invocation + glob-string-presence semantics. Task 0 anticipated this — the plan explicitly says "mechanism per Task 0".
2. **The plan's `inspect-context.sh` placeholder used Node.js `require()`** — substituted with the Python `python3 _bmad/scripts/resolve_customization.py --skill <dir> --key agent.persistent_facts` invocation.
3. **The plan's awk-based CSV verification command in Task 5** was naive about quoted commas. The CSV is valid (per `csv.DictReader`); only the verification was buggy. Non-blocking.
4. **The plan's heredoc commit-message in Task 1** had a stray `git add` line in the message body when copy-pasted into a subagent prompt. The plan file itself was correct; the controller introduced the error during prompt construction. Amended in-place; noted for the future-prompt-construction discipline.
