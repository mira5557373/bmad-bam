| Metric | Value |

| **BAM V2 Templates** | 48 files in `src-v2/data/templates/` |

## Consolidated Gap Inventory

### 🔴 Critical Gaps (5 Total)

| ID | Gap | Source | Description | Impact | Remediation |
|----|-----|--------|-------------|--------|-------------|
| **C1** | Missing `stepsCompleted` | Both | BAM templates lack workflow step tracking array | BMAD workflows cannot resume mid-workflow | Add `stepsCompleted: []` to frontmatter |
| **C2** | Missing `inputDocuments` | Both | BAM templates lack input artifact registry | BMAD loses document traceability | Add `inputDocuments: []` to frontmatter |
| **C3** | Missing `workflowType` | Both | No workflow type identifier | BMAD routing/validation may fail | Add `workflowType: 'bam-*'` to templates |
| **C4** | BMB Registry Missing | Report 2 | `bmb-registry-entry.yaml` not in official registry | Templates won't install via `npx bmad-method install` | Submit PR to BMB registry |
| **C5** | Missing Handlebars Block Helpers | Report 1 | BAM templates don't use `{{#each}}`, `{{#if}}` | Cannot generate dynamic lists/conditionals | Add iteration support or document limitation |

### 🟠 Medium Gaps (5 Total)

| ID | Gap | Source | Description | Impact | Remediation |
|----|-----|--------|-------------|--------|-------------|
| **M1** | Centralized vs Co-located | Report 2 | BAM uses `data/templates/`; BMAD uses per-skill `templates/` | Cross-skill sharing is non-standard | Document as BAM module convention |
| **M2** | Fill-in vs Append-only | Report 2 | BAM uses `<!-- FILL -->` markers; BMAD appends sections | Different document construction models | BAM skills handle internally |
| **M3** | Missing `lastStep` | Report 2 | No resume pointer for multi-step workflows | Cannot resume research-style workflows | Add `lastStep: 1` where needed |
| **M4** | Missing frontmatter metadata | Report 2 | `project_name`/`user_name` only in body, not frontmatter | BMAD template initialization may fail | Add to frontmatter for compatibility |
| **M5** | Missing CRITICAL checklist item | Report 1 | `validation-report.md` lacks `**CRITICAL:**` pattern | Inconsistent quality gate format | Add `**CRITICAL:**` item |

### 🟡 Minor Gaps (4 Total)

| ID | Gap | Source | Description | Remediation |
|----|-----|--------|-------------|-------------|
| **L1** | Extra BAM metadata fields | Both | `category`, `version`, `type`, `web_research_enabled`, `source_verification` | Keep — useful for BAM tooling |
| **L2** | `related_patterns` field | Both | 8 BAM templates have this; BMAD doesn't use it | Keep — BAM cross-reference value |
| **L3** | `> Generated by` attribution | Report 1 | BAM templates have workflow attribution; not BMAD standard | Keep — useful for traceability |
| **L4** | BAM-specific variables | Both | `{{tenant_id}}`, `{{ai_runtime}}`, `{{tenant_model}}` | Expected — domain extension |

## Placeholder Syntax Comparison (Validated)

### ✅ Compatible: Simple Substitution

```markdown
# {{project_name}} - Title
**Date:** {{date}}
**Author:** {{user_name}}
```

### ❌ Gap: Handlebars Block Helpers

**BMAD uses (BAM does not):**

```handlebars
{{#each files_in_inventory}}
### `{{file_path}}`
**LOC:** {{line_count}}
{{#each exports}}
- `{{name}}`: {{type}}
{{/each}}
{{/each}}

{{#if has_api_docs}}
- [API Contracts](./api-contracts.md)
{{/if}}
```

**BAM equivalent (static structure):**

```markdown
<!-- FILL: Add one row per file -->
| File | LOC | Exports |
|------|-----|---------|
|      |     |         |
```

**Impact:** BAM templates cannot dynamically generate variable-length lists. Suitable for fill-in-the-blank workflows but not for automated document generation.

## Template Location & Installation (Validated)

### Directory Structure

| System | Template Location | Namespace |
|--------|-------------------|-----------|
| BMAD BMM | `src/bmm-skills/{skill}/templates/` | Per-skill (private) |
| BAM V2 | `src-v2/data/templates/` | Centralized (shared) |

### Installation Paths (`module.yaml`)

```yaml
install:
  data:
    source: data/
    target: "{project-root}/_bmad/bam/data/"  # Includes templates/
```

**Result:** BAM templates install to `_bmad/bam/data/templates/` — separate namespace from BMAD's `_bmad/skills/*/templates/`. No naming conflicts.

### Registry Gap (C4)

Until `bmb-registry-entry.yaml` is added to official BMB registry:
- `npx bmad-method install` ignores BAM's `data/` directory
- Templates must be manually copied or installed via workaround

## Conclusion

The two reports identified **complementary gaps**:

- **Report 1** correctly identified: Handlebars block helper gap (C5), CRITICAL checklist gap (M5)
- **Report 2** correctly identified: BMB registry gap (C4), lastStep gap (M3), frontmatter metadata gap (M4)
- **Both identified:** Core workflow state gaps (C1-C3), structural differences (M1-M2)

**Total unique gaps: 14** (5 critical, 5 medium, 4 minor)

**Estimated remediation time:** 4-5 hours for full compatibility

The systems are designed to be **complementary** — BAM extends BMAD into multi-tenant SaaS territory without conflicting with existing BMAD templates. With the identified remediation, full interoperability is achievable.
